# TESTING.md — чек-лист ручного тестирования APK Биомашины

Цель документа — за 60–90 минут на реальном устройстве пройти все критичные сценарии и зафиксировать баги. Минимум 60 пунктов в 17 секциях.

Формат прохода: устанавливаем свежий debug-APK на чистое устройство (или после удаления приложения), включаем секундомер и идём по списку сверху вниз. На каждый failing пункт — запись в раздел [«Реестр найденных багов»](#реестр-найденных-багов).

Условные обозначения:
- `[ ]` — не проверено
- `[x]` — проверено, OK
- `[!]` — проверено, баг (см. реестр)

---

## 1. Установка (6)

- [ ] APK скачан с GitHub Actions (artifact `biomachine-debug-apk`), ZIP распакован.
- [ ] В системе включено «Разрешить установку из этого источника» для приложения, через которое открываем APK.
- [ ] Установка через файловый менеджер прошла без ошибок (`Package appears to be invalid` не вылазит).
- [ ] Иконка приложения «Биомашина» появилась в лаунчере (оранжевый фон, читаемая на любых обоях).
- [ ] Первый тап на иконку — приложение запускается без краша.
- [ ] Splash-экран показывается ≈ 1.0–1.5 сек, затем плавный переход в UI.

## 2. Онбординг (5)

- [ ] Шаг 1 (Welcome): анимация и текст приветствия отображаются, кнопка «Далее» активна.
- [ ] Шаг 2 (Architecture): отображаются 6 мезоциклов (Pre-Week, M1, Deload 1, M2, Deload 2, M3) с правильными неделями.
- [ ] Шаг 3 (Setup): поле «Имя» принимает кириллицу + латиницу + emoji.
- [ ] Кнопки выбора «🚀 Начинаю Pre-week сегодня» и «📥 У меня уже есть данные» — обе кликабельны, активный вариант визуально подсвечивается оранжевым, неактивный серым; переключение между ними работает в обе стороны.
- [ ] После нажатия «Начать! 🤖» открывается Dashboard, повторный запуск приложения не показывает онбординг снова.

## 3. Разрешения (4)

- [ ] При первом запуске Android 13+ показывает диалог запроса POST_NOTIFICATIONS — кнопка «Разрешить» работает.
- [ ] При попытке сделать прогресс-фото (Tests → камера) запрашивается CAMERA permission.
- [ ] Отказ в POST_NOTIFICATIONS не крашит приложение, просто не приходят локальные уведомления (тосту в логе можно).
- [ ] Отказ в CAMERA не крашит приложение, кнопка прогресс-фото сообщает об отсутствии разрешения, остальной UI работает.

## 4. Dashboard (5)

- [ ] Hero-блок показывает текущую неделю (или Pre-Week если week=0) и название мезоцикла.
- [ ] Виджеты «Сон», «Пульс покоя», «Вес», «Настроение», «Шаги» отображаются с targets.
- [ ] Кольца нутрициологии (kcal / protein / water) отображаются и обновляются при добавлении приёма пищи.
- [ ] Кнопка «Сегодняшняя тренировка» ведёт на правильный day (по WEEK_DAYS schedule) или показывает «Отдых» в воскресенье.
- [ ] Pre-Week (week=0): фиолетовый блок c подсказкой «Заполни baseline-тесты» + CTA «Открыть тесты», прогресс не показывается как 0% от 12 недель.

## 5. Тренировка (6)

- [ ] WorkoutSelectScreen открывается с кнопок выбора A / B / C / R / D / E (по WEEK_DAYS).
- [ ] Загружается правильный список упражнений из `data/programData.ts` для выбранного дня и текущего мезоцикла.
- [ ] Для каждого подхода поля «Вес», «Повторы», «RPE», «Заметка» принимают ввод и сохраняются в state.
- [ ] Чекбокс подхода тапается — срабатывает haptic light.
- [ ] Нажатие «Завершить» сохраняет WorkoutLog (timestamp, duration, RPE, notes, exercises).
- [ ] Возврат на Dashboard после выхода из тренировки — данные подхода не теряются (если тренировка была сохранена).

## 6. Таймер отдыха (КРИТИЧНО) (8)

- [ ] Таймер запускается с пресетов 60 / 90 / 120 / 180 секунд и кастомного значения.
- [ ] За 3 секунды до конца проигрывается короткий beep (`beep.mp3`).
- [ ] В момент окончания играет финальный звук (`finish.mp3`) длительностью ≈ 0.6 сек.
- [ ] В момент окончания срабатывает **heavy** виброотклик (`Haptics.impact({ style: 'HEAVY' })`).
- [ ] При заблокированном экране: звук + вибро + локальное уведомление приходят вовремя (±1 сек).
- [ ] В silent mode звук таймера всё равно играет — NativeAudio обходит mute (играет на STREAM_MUSIC, not STREAM_NOTIFICATION).
- [ ] При свёрнутом приложении (HOME → другое приложение) локальное уведомление приходит в правильное время.
- [ ] Возврат в приложение через свайп из recents — таймер показывает корректное оставшееся время (без перезапуска); кнопки ±15 сек работают и пересчитывают таргет timestamp.

## 7. Keep awake (3)

- [ ] Во время активной тренировки экран не гаснет даже при выставленном auto-lock 15 секунд.
- [ ] Во время активного RestTimer экран не гаснет.
- [ ] После выхода из тренировки и из таймера экран засыпает в нормальном системном таймауте (не остаётся всегда включённым).

## 8. Камера (прогресс-фото) (4)

- [ ] Кнопка прогресс-фото в TestsScreen открывает Camera UI или диалог выбора (камера / галерея).
- [ ] После съёмки фото появляется в сетке тумбнейлов на экране.
- [ ] Тап на тумбнейл открывает фото в полноэкранном режиме с кнопкой удаления.
- [ ] После перезапуска приложения фото остаются на месте (Preferences хранит webPath).

## 9. Экспорт / импорт данных (4)

- [ ] Settings → Export JSON → файл сохраняется в `Documents/biomachine-export-YYYY-MM-DD.json` или открывается Share-меню.
- [ ] Открытый JSON валидный (parse без ошибок) и содержит все секции: user, dailyLogs, workouts, tests, achievements, progressPhotos.
- [ ] Settings → Export CSV (если реализован) — файл с заголовками и строками выгружается.
- [ ] Settings → Import JSON → выбор файла → данные восстанавливаются, текущие перезаписываются.

## 10. Уведомления-напоминания (5)

- [ ] Settings → Уведомления — 4 тумблера (workout, metrics, creatine, water) переключаются.
- [ ] Time-picker рядом с каждым тумблером открывается, время сохраняется и отображается.
- [ ] Утреннее напоминание (metrics) приходит в заданное время следующего дня.
- [ ] Отключение тумблера сразу отменяет запланированное уведомление (не приходит в назначенное время).
- [ ] Напоминания персистят после перезагрузки телефона (BOOT_COMPLETED + RECEIVE_BOOT_COMPLETED permission в манифесте).

## 11. Метрики и графики (3)

- [ ] MetricsScreen открывается без лагов, переключение между «Вес / Сон / HR / Сила» работает.
- [ ] Recharts рендерят данные за последние 30 дней без ошибок (NaN, infinite loop).
- [ ] На узких экранах (480×800) графики не выходят за viewport, нет горизонтального скролла страницы.

## 12. Сон и восстановление (3)

- [ ] SleepScreen: ввод bedtime / wakeup сохраняется, calcDuration корректно учитывает переход через полночь.
- [ ] Кнопка таймера мобильности «10 мин» открывает полноэкранный RestTimer на 600 секунд (фикс из Phase 3).
- [ ] BreathingTimer (box, 4-7-8) запускается, циклы фаз сменяются, кнопка «Пауза» работает.

## 13. Тесты и gate-проверки (3)

- [ ] Pre-Week: все 16 полей из TEST_FIELDS принимают ввод и сохраняются.
- [ ] Gate-проверки на неделях 5/9/12: pull-ups ≥ 6, push-ups ≥ 25, dips ≥ 10, nordic curl ≥ 5, jump +10 см, sleep ≥ 7.5ч 14 дней — каждая проверка показывает зелёный/красный статус правильно.
- [ ] Mini-retest на 5 и 9 неделях: данные не перезаписывают Pre-Week, сохраняются как отдельные записи.

## 14. Персистентность данных (3)

- [ ] Свайп приложения из recents → повторный запуск → онбординг не показывается, все данные на месте.
- [ ] Перезагрузка телефона → данные на месте, запланированные напоминания всё ещё работают.
- [ ] `adb install -r` (переустановка с сохранением данных) — данные на месте, миграции схемы (если есть) отрабатывают.

## 15. Производительность (4)

- [ ] Переходы между экранами плавные (60 fps на средних устройствах, 90+ на флагманах).
- [ ] При простое (приложение в фоне) телефон не нагревается.
- [ ] За ночь в фоне расход батареи < 2% (Settings → Батарея → Биомашина).
- [ ] Размер установленного приложения < 50 МБ (Settings → Приложения → Биомашина → Размер).

## 16. Специфика OEM-прошивок (4)

- [ ] **Xiaomi/Redmi (MIUI/HyperOS):** включён «Автозапуск» + «Без ограничений» в Контроле активности → уведомления приходят.
- [ ] **Xiaomi:** включена фоновая активность → таймер в свёрнутом виде не убивается через 5 минут.
- [ ] **Samsung:** Биомашина не попадает в «Глубокий сон» / «Спящие приложения» → background timer работает.
- [ ] **Huawei/Honor:** в «Защищённых приложениях» / «Управлять вручную» включены автозапуск + работа в фоне.

## 17. UI / Safe-area / Theming (2)

- [ ] BottomNav на устройствах с жестовой навигацией (Android 10+) не перекрывается системным баром (фикс `.pb-safe` из Phase 3).
- [ ] Status bar читаемый (тёмные иконки на оранжевом фоне или белые на тёмном) — нет белого текста на белом.

## Реестр найденных багов

| № | Экран | Описание | Repro шаги | Приоритет | Статус |
|---|---|---|---|---|---|
| 1 | | | | P0/P1/P2 | Open / Fixed / Won't fix |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

**Приоритеты:**
- **P0 (блокер):** приложение не запускается, теряет данные, краши на основном flow.
- **P1 (важный):** сломан критичный сценарий (таймер, экспорт, тренировка), но workaround есть.
- **P2 (косметический):** UI-неточности, локализация, edge cases на узких экранах.
